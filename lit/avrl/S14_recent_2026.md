# S14: Newest 2026 work on verification budgets, selective verification, and reward computation cost

## 1. What this angle contributes to the thesis

This angle establishes that "verification is the bottleneck cost in RL post-training" is now an active 2026 cluster, not just SOFisher's framing borrowed from microscopy. The seed paper (arXiv 2606.15841) shows the field has already moved past uniform thresholds toward heterogeneity-aware allocation, a weaker cousin of AVRL's learned, per-group allocator. The TTRL-adjacent 2025-2026 cluster on majority-vote reward failure independently documents the failure mode AVRL targets: a cheap proxy that looks fine on average but is locally exploitable, direct support for "proxy error clusters in prompt space." Nothing found here trains the allocator with RL, in-training, under a hard expensive-call budget cap, while tracking corrupted-reward rate; that gap is open for AVRL.

## 3. What supports the thesis claim, what threatens it

**Supports:**
- Source 1 (seed) shows static allocation is regime-dependent: cost-stratified thresholds only help where proxy quality is heterogeneous, framed as "structural heterogeneity limits optimization gains" for *non-learned* schemes: consistent with AVRL's premise that a fixed threshold leaves value on the table and a learned allocator that detects where the proxy is locally bad should do better.
- Sources 12-16 form a tight, independent empirical trail showing majority vote (the standard cheap proxy in RLAIF/RLVR) has documented, localized failure modes (extinction windows, distributional collapse) that fixed-weight consensus only partially fixes. This is direct evidence for "the proxy is exploitable in clusters," the load-bearing claim behind AVRL's prompt-space-structure angle.
- Sources 4 and 7 show the field already treats judge/rollout budgets as an explicit constrained-optimization object (inverse-variance allocation, budget-conditioned policy optimization), so a budget-capped in-training allocator is a natural extension, not a foreign framing.
- Source 8 gives a theoretical floor: verifier-based approaches provably beat verifier-free ones asymptotically, arguing against "just skip verification entirely."

**Threatens:**
- No 2026 source found trains the allocator with RL, in-training, jointly with the policy, under a hard expensive-call budget, while measuring corrupted-reward rate. Every allocator found (1, 4, 5, 6, 7) is a fixed rule, a convex/bandit-style solver run once per batch, or a confidence-based self-check, not a learned sequential-decision allocator that adapts online to where the proxy is exploitable. This gap could be open territory, or it could be open because a static/convex allocator already captures most of the gain more cheaply (source 1 itself: non-learned partitioning "avoided unnecessary complexity when partitioning proved unhelpful"), which threatens "learned beats fixed at equal budget."
- Source 8's asymptotic result concerns verifier-vs-no-verifier, not learned-vs-fixed allocation, and should not be overclaimed as support.
- OpenAlex shows zero citations of or from the seed paper, so the "cites / cited-by" half of this brief could not be run via citation graph; sources above came from keyword search instead, a weaker sweep to recheck once OpenAlex indexes this preprint.

## 4. Closest prior work from this angle, and how AVRL differs

The closest single paper is source 1, Yang (2026), *Heteroskedastic Signals in Budgeted LLM Verification* (arXiv:2606.15841), the explicit seed of this search. It shares AVRL's framing (a verification budget, a cheap proxy signal, a decision of when the proxy is trustworthy enough to skip the expensive check) and the finding that naive uniform allocation underperforms because signal quality is heterogeneous across the prompt/cost space. It differs from AVRL in three ways: (a) its rule is diagnostic and threshold-based per cost region, chosen by testing whether heterogeneity exists, not a policy learned end-to-end; (b) it operates at evaluation time on MBPP/MATH with a static signal, not inside an RL training loop where the policy and proxy exploitability both move; (c) it reports hit-rate gains, not corrupted-reward rate or downstream RL stability, so it cannot support or refute AVRL's "fewer corrupted rewards" claim: that comparison still has to be built from scratch.
