## The idea, in plain language

The project already found, on math and code, that a model's own agreement with itself (does it give the same answer across N tries) predicts when its cheap grader is wrong, almost as well as anything more complicated (AUC 0.87 to 0.93), and that a fixed rule built on this (verify only the split-vote groups) is close to the best you can do. The proposal here is to stop treating that as a GSM8K-specific fact and treat it as the general cheap grader: for any task, sample N answers, measure how much they agree, and spend the expensive grader only on the prompts where the model disagrees with itself. For free text, where there is no exact answer to vote on, replace exact-match agreement with embedding similarity among the N sampled answers. The claim to test is narrow: does this agreement signal, extended this way, also work on the open-ended task where the project's reward-model proxy is weak (AUC 0.75 to 0.80), or is the reward model still better there.

## The mechanism, precisely

1. Sampling. For each prompt in a GRPO rollout group, use the N completions already being sampled for the policy update (N equal to the group size, 4 to 8 in the existing harnesses); no extra generation cost.
2. Confidence score. For tasks with a discrete final answer (math, code): cluster completions by exact-match answer, confidence c = size of the largest cluster divided by N, exactly the existing majority-vote statistic. For free text: embed each completion, compute the mean pairwise cosine similarity among the N embeddings, c = that mean (or, for a cluster-shaped analogue, the largest single-linkage cluster at a similarity cutoff, divided by N).
3. Gate. Groups with c at or above a threshold tau are "confident": accept the cheap grader's answer (majority answer, or the embedding centroid-nearest completion) as the reward, no expensive call. Groups with c below tau are "split": route to the expensive grader.
4. Picking N online. Start at N=4. For borderline groups (c close to tau after 4 samples), draw more completions up to an N_max set by the per-step compute budget, stopping early once a bootstrap over subsamples of the drawn completions shows c's standard error below a small tolerance; confident and clearly-split groups resolve in 4 samples, only the ambiguous middle needs more.
5. Picking tau online. Do not fix tau once. Recalibrate every batch as a percentile: tau = the value such that exactly the budgeted fraction B percent of the batch's groups fall below it. This tracks drift automatically, since the confidence distribution shifts (usually upward) as the policy improves during training, so an absolute tau fixed at step 0 would under-spend the verification budget later; a percentile-relative tau holds the budget fixed by construction.

This is the same shape as the project's existing threshold allocator, generalized along two axes: the confidence statistic (embedding similarity in place of exact-match vote) and the calibration rule (online percentile in place of a value fit once on held-out data).

## Prior art

- Self-Consistency (Wang et al., 2022; ICLR 2023), https://arxiv.org/abs/2203.11171. Sampled N reasoning paths and majority-voted the final answer at inference time to raise accuracy. Agreement is informative, but only used to pick an answer, never as a confidence signal for when to pay for a second grader, and not inside RL training.
- TTRL (Zuo et al., 2025), https://arxiv.org/abs/2504.16084. Uses majority vote over N samples as the reward itself, no verifier at all, for test-time RL on unlabeled data; reports large gains on AIME with Qwen-2.5-Math-7B. Proves majority vote can fully substitute for a verifier on math, but never pays for ground truth, so it cannot catch the systematic majority-vote errors measured directly here (12 to 58 percent proxy error rate).
- Spurious Rewards (Shao et al., 2025), https://arxiv.org/abs/2506.10947, and Dual Consensus (Du et al., 2026), https://arxiv.org/abs/2603.16223. Show label-free RLVR with vote-shaped rewards trains well even when partly wrong; Dual Consensus patches the "spurious majority" failure with a fixed, non-learned, two-stage vote correction. Closest existing fixed-rule competitor to the gate proposed here, but none frame it as a budgeted-verification problem, measure its AUC against ground truth, calibrate a threshold online against a spending budget, or touch free text.

## The exact novelty claim that survives

No new estimator is being proposed; agreement-as-confidence is self-consistency, agreement-as-reward is TTRL, and fixed vote-correction rules exist (Dual Consensus). What is new is narrow: (a) measuring self-consistency's AUC as a verification-gating signal, already done for math and code but not for free text; (b) an online, percentile-based tau that tracks distributional drift during training, which no cited paper does, they either fix a threshold once or do not threshold at all; (c) the open question of whether embedding-similarity self-consistency on free text beats the reward model's AUC 0.75 to 0.80. If it does not, this adds nothing beyond one more candidate cheap grader; the project's two-regime finding stands. If it does beat 0.80, self-consistency becomes a free, label-free alternative to training a reward model in the weak-signal regime, worth reporting on its own.

## The product angle

A thin wrapper around TRL GRPO. A user points it at their LoRA policy, task type (math, code, free text), and a verification budget (percent of groups, or a dollar figure), for example `avrl.train(model, task, expensive_grader=my_judge_fn, budget_pct=25)`. It samples N completions per prompt (already happening for GRPO), scores agreement the right way for the task type, recalibrates the threshold each batch to hit the stated budget, and calls the user's expensive grader, an API judge, a paid human-labeling endpoint, or ground truth, only on the disagreeing groups. What the user sees while training: a running count of expensive calls against the budget, a corrupted-reward-admission counter, and an accuracy curve.
