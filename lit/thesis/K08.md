# K08: Adversarial Prior-Art Hunt on H8 (Targeted Synthesis)

## Verified numbers on the three cited "closest" papers

- **2512.00884** (Active Synthetic Data Generation for Finetuning LMs, https://arxiv.org/abs/2512.00884): active/uncertainty selection (student loss on greedy decodes) needs **1.3x-2x fewer samples** than random/static generation to match performance across four datasets; random needs **33-100% more SFT data** for equal performance. Critically, selection is **per-example**, using a simple ranking criterion recomputed each round — not per-skill-region, and not a trained bandit/RL policy. The paper explicitly finds simple cheap criteria beat more complex ones (BADGE, reward scoring).
- **DataEnvGym** (https://arxiv.org/abs/2410.06215): skill-tree/skill-list state conditioning gives real gains over stateless generation — e.g. MATH +7.66pp (15.78 to 23.44), GQA +5.58pp, LiveCodeBench +2.41pp (Table 2). But the loop retrains the full student each iteration (10 epochs GQA, 3 epochs MATH/code) and re-evaluates on the full validation set to get the next state — there is no cheap-probe layer at all; "state" costs as much as the expensive measurement in this thesis's framing.
- **SwS** (https://arxiv.org/abs/2506.08989): +10.0% avg (7B), +7.7% avg (32B) across eight reasoning benchmarks. Weakness identification is a **single static pass** during a preliminary RL phase (fixed failure criterion, one budget allocation via a fixed equation), not online rebudgeting.
- **2601.10109** (Skill-Aware Data Selection for Reasoning Distillation, https://arxiv.org/abs/2601.10109): +1.6% (Qwen3-4B), +1.4% (Qwen3-8B) selecting 1k of 100k existing examples by weak-skill priority. This is **selection from a fixed pool**, not generation, and is a one-time prioritization, not sequential.

## Strongest reason a committee says "already done"

2512.00884 already empirically confirms the thesis's core causal claim — that cheap-signal-driven adaptive selection beats static/uniform generation at matched budget — and does so at **finer granularity** (per-example) than what H8 proposes (per-region). A region-level bandit is a coarsening of that already-validated mechanism: it can only add value if region-level allocation beats per-example active selection, not merely beats a static region ranking. The thesis's own Kill Criteria (section 6) only require beating a static error-ranked baseline by 5% — a bar 2512.00884 has arguably already cleared at a different granularity. A committee will ask why the harder, more informative comparison (region-bandit vs. per-example active learning, the actual current SOTA) isn't the pre-registered bar.

## Judgment

The literature robustly proves "targeting helps" (three independent papers, real numbers). What is not demonstrated anywhere found here is a region-level sequential policy benchmarked against per-example active selection (not just against static region-ranking) at equal verified-example budget. That is narrower than H8 as currently scoped, and the thesis document does not set this as the bar to beat.
