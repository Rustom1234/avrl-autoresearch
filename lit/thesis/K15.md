# K15: Adversarial Prior-Art Check on H15 (Active Prompt Selection for RLVR)

## Verified numbers on the 3 closest works

**PCL** (arXiv:2510.01135, https://arxiv.org/abs/2510.01135): abstract confirms "12.1x and 16.9x faster speed on identifying intermediate-difficulty prompts when training on MATH and DeepScaleR" via a concurrently-updated value model. Matches H15's citation exactly. Abstract does not state whether the value model generalizes to unseen prompts via embedding neighbors or requires per-prompt updates; UNVERIFIED without full text.

**DAPO** (arXiv:2503.14476, https://arxiv.org/abs/2503.14476): abstract confirms "50 points on AIME 2024 using Qwen2.5-32B." The H15 claim that this used "50% of the training steps" of DeepSeek-R1-Zero-Qwen-32B is UNVERIFIED from the abstract alone (likely a body/table figure, not independently re-confirmed here).

**MoPPS** (arXiv:2507.04632, https://arxiv.org/abs/2507.04632): abstract confirms it "models each prompt's success rate as a latent variable" and does "streaming Bayesian inference" plus "posterior sampling in a constructed multi-armed bandit." This is explicitly **per-prompt scalar tracking**, not embedding-neighborhood generalization to unseen prompts. Supports H15's own framing that this specific mechanism is not what MoPPS does.

## Adversarial search for embedding-neighborhood transfer

arXiv API queries combining "embedding," "prompt selection"/"prompt embedding," "difficulty," "RLVR"/"reinforcement learning" (2026-dated results) returned no paper explicitly framing RLVR prompt selection as embedding-neighborhood transfer of difficulty to unseen prompts. https://arxiv.org/abs/2603.09065 surfaced but uses prompt embeddings for decoding-strategy selection, not RL prompt/curriculum selection — not a match.

The one genuine near-miss is **PPM** (arXiv:2602.01970, Feb 2026, https://arxiv.org/abs/2602.01970), already in H15's own list (item 7). Abstract confirms: "a lightweight generative model trained on the shared optimization history" that "generalizes at test-time for efficient computational allocation," reporting "substantial improvements in training efficiency, final performance, and test-time efficiency over superior baseline methods" (no numbers given). This is a small model predicting prompt difficulty that **generalizes across prompts it has not individually tracked** — functionally the same capability H15 proposes to test as its "genuinely novel" contribution (embedding-neighborhood generalization vs scalar per-prompt tracking).

## Strongest "already done" argument

A neural model that "generalizes at test-time" to prompts it hasn't rolled out (PPM) can only do so through some learned representation of prompt content — in practice this is an embedding space, whether or not the authors use that word. H15's section 3 distinguishes itself by framing prompt selection as a "sequential decision problem" exploiting embedding autocorrelation (the SOFisher DQN framing), but PPM already delivers the functional outcome (generalization to unseen prompts via a learned predictor) five months before H15's Phase 1 would start. The SOFisher "sequential decision" language risks being a relabeling of PPM's mechanism rather than a new capability — a committee could reasonably say PPM already closes the gap H15 calls open, pending confirmation PPM's generalization is not embedding-based (UNVERIFIED from abstract).

## Judgment

The field is crowded and the specific ablation H15's own kill criteria (Section 6) already names — embedding-neighborhood vs scalar-bandit, head-to-head, one harness — has not been confirmed to exist yet, but PPM makes it likely close. H15's kill criteria are honest about this risk already, which is a good sign for defensibility, not a fatal one.
