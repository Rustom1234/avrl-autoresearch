# H20 — Active Query Selection for Knowledge Distillation

## 1. Hypothesis and SOFisher mapping

A policy that chooses which inputs to query a frontier teacher on next, using cheap student-side signals (entropy, disagreement with a cheap proxy, embedding neighbourhood) and exploiting autocorrelation of teacher-label value across similar inputs, reaches a target student quality with far fewer teacher calls than uniform querying, and keeps adapting as the student improves. This is the student-driven analogue of SOFisher's field-of-view policy: the "tissue slide" is input space, the "rare target" is a high-value training example (one the student gets wrong or disagrees with the teacher on), the "expensive measurement" is a teacher forward pass, and the "cheap state features" are entropy, proxy-model disagreement, and embedding position, none of which alone rank inputs as well as the teacher label does.

5. **Gemma 2 Technical Report (2024).** https://arxiv.org/abs/2408.00118 — Confirms the **2B and 9B** Gemma 2 models were trained with knowledge distillation (citing Hinton 2015) instead of next-token prediction; no per-token distillation budget number was retrievable from the abstract this session.

## 3. What is genuinely open as of 2026, and why a year is needed

The verified prior art establishes three separate pieces but not their combination: (a) that teacher-generated data has strongly non-uniform value and can be subsampled after the fact (LESS, DSIR, AlpaGasus, Distilling Step-by-Step), (b) that on-policy / self-generated data improves distillation efficiency (MiniLLM, GKD), and (c) that production labs already spend distillation compute deliberately on smaller models (Gemma 2). None of the verified papers describe a closed-loop, sequential policy that decides, call by call, which unlabeled input to send to the teacher next, using only cheap student-side signals, while the student is still training. LESS and DSIR select once, largely statically, using either gradients against a fixed target set or n-gram importance weights, not a live entropy/disagreement/embedding policy that adapts as the student's error surface shifts. AlpaGasus filters with an LLM judge as a one-shot quality gate rather than a sequential acquisition function. Whether a lightweight RL or bandit policy over cheap features actually tracks the moving target of "where does this student currently disagree with the teacher" — rather than just re-discovering static importance sampling — is an empirical question with no verified answer in hand. A year is needed because this requires: a working entropy/disagreement/embedding acquisition function, a stopping/refresh schedule as the student improves (the target itself moves, unlike SOFisher's fixed tissue geography), and comparison against strong static baselines (LESS, DSIR-style, random) at multiple budget levels before any claim of "far fewer teacher calls" is defensible.

## 4. Three-condition check

- **Spatial (input-space) autocorrelation of value:** DSIR and LESS both show that data value clusters — DSIR's importance weights and LESS's gradient-similarity selection both outperform random sampling by exploiting that similar inputs have similar training value (arxiv 2302.03169, arxiv 2402.04333). This supports the SOFisher precondition that value is autocorrelated in input space, though neither paper tests a live sequential policy.
- **Expensive measurement, cheap state:** A teacher forward pass (a frontier LLM API call) is definitionally far more costly than computing student entropy or an embedding lookup; this is the same cost ratio that motivates all the data-selection papers above (why filter/select at all rather than label everything) — qualitative support only, no single verified cost-ratio number was retrieved this session (UNVERIFIED for an exact multiplier).
- **Cheap features alone cannot rank targets:** DSIR explicitly benchmarks importance-resampling against heuristic filtering and beats it by 2-2.5% on GLUE (arxiv 2302.03169), showing cheap heuristics underperform smarter, target-aware selection — indirect evidence that raw cheap signals (e.g., entropy alone) leave value on the table, consistent with needing the proposed policy rather than a static cheap-feature filter.

## 5. Year plan

**Phase 1 (months 1-3, literature closure + first experiment):** Close the gaps in items 11-12 above with a proper search pass (this session's budget was exhausted before this could be done). Week-1 experiment on 4 A100s: 7B teacher (open-weight, e.g. a Qwen or Llama-class model already on hand), 0.5B-1B student, fixed pool of ~50-100k unlabeled instruction-style inputs. Compare adaptive query selection (entropy + embedding-neighbourhood policy) vs uniform random querying at matched teacher-call budgets (e.g. 5%, 10%, 20% of pool). Metric: **student task accuracy per teacher call** (accuracy on a held-out eval vs cumulative teacher calls used), not accuracy per token. Strongest existing baseline to beat: **DSIR-style static importance selection** (arxiv 2302.03169) and/or **LESS-style gradient selection** (arxiv 2402.04333), both run once at the same budget levels for a fair comparison, since neither is a live adaptive policy and both are the closest verified precedent.

**Phase 2 (months 4-8):** If phase 1 shows adaptive beats static selection beats random at matched budget, scale student/teacher sizes and test whether the policy needs retraining/refresh as the student improves (the moving-target problem flagged in section 3). Ablate which cheap signal (entropy vs proxy disagreement vs embedding neighbourhood) drives the gain.

**Phase 3 (months 9-12):** Test transfer to a second domain/task family and a larger teacher if budget allows; write up compute-savings curve (teacher calls saved at fixed final quality) as the headline result.

## 6. Kill criteria

- If in phase 1 the adaptive policy does not beat static DSIR/LESS-style one-shot selection at any matched budget after two tuning passes, kill the "sequential/adaptive" framing and fold any residual gain into a static-selection paper instead.
- If entropy/disagreement/embedding signals correlate with teacher-student disagreement at less than a weak effect size (spot-checked in week 1 before the full run), kill before spending the full compute budget — this directly tests the "cheap features are informative but insufficient alone" precondition.
- If gains disappear once compared against a matched-cost uniform-random baseline with the same total forward passes (i.e., the gain was just "more compute" mislabeled as "smarter selection"), kill.

## 7. Impact on a lab's stack

If it works, this changes how a lab distils: instead of a fixed synthetic-data generation budget spent uniformly (as Gemma 2's reported approach appears to be), teacher-call budget becomes a controllable dial with a measured accuracy-per-call curve, directly cutting frontier-API or frontier-inference cost for every future student trained from the same teacher, and it composes with existing static selection (LESS/DSIR) as a warm start rather than replacing it.
