# AR5 implementation spec: live routed autoresearch loop (one 8-hour block, five arms)

Status: frozen design, 2026-10-17. Implementers read this in full. Shell scripts in bash, Python with /homes/rdubash/yes/bin/python. No em dashes anywhere. New files only under avrl/exp/, avrl/autoresearch.live.js, /homes/rdubash/avrl_live/. Never modify the originals (avrl/RESEARCH_LOG.md, lit/avrl/EXPERIMENT_BACKLOG.md, avrl/PROJECT.md, avrl/runs/, avrl/p0_*.py); the orchestrator alone appends ledger entries.

## 1. Question

In the real autoresearch loop (planner, runner, analyst, critic), does routing a cheap model (Haiku) to the first three roles with a strong critic (Sonnet) reach the same claim verdicts as the all-Sonnet loop at a fraction of the cost, with an independently audited ledger error rate not materially worse; does an all-Haiku loop do worse; and does a cascaded critic (two Haiku screeners, escalate to Sonnet on flag or disagreement) save critic calls without losing quality? Analogue of the RL arms: full verification, proxy plus verifier, proxy only, confidence-threshold cascade.

## 4. Per-run trees: exp/ar5_make_run.sh <run_id> <host>

cp -a the seed to /homes/rdubash/avrl_live/<run_id>/ (BASE). Substitute {BASE} in lit/avrl/EXPERIMENT_BACKLOG.md with the real BASE path. Write BASE/HOST (one line). Create BASE/bin/ with three helpers (identical text in every run, parameterized only by files in BASE):
- bin/gpu_run.sh <run_dir> <command...>: creates run_dir; if HOST equals $(hostname -s) runs locally, else via ssh -o BatchMode=yes HOST; environment on the target: cd BASE/avrl; export CPATH=$HOME/.local/include/python3.12 HF_HUB_OFFLINE=1 VLLM_CACHE_ROOT=/tmp/avrl_<run_id>/vllm TRITON_CACHE_DIR=/tmp/avrl_<run_id>/triton; launches `setsid nohup timeout 2700 bash -c '<command>; echo $? > <run_dir>/exit_code; touch <run_dir>/done.flag' > <run_dir>/run.log 2>&1 < /dev/null &` and writes the remote PGID to run_dir/pgid. Prints the run_dir and "launched".
- bin/gpu_kill.sh <run_dir>: kills the PGID on HOST (kill -- -PGID), waits 10 s, then `pkill -u rdubash -f '<BASE>/avrl/.*[.]py'` on HOST, then prints nvidia-smi --query-compute-apps and memory used.
- bin/gpu_status.sh: prints nvidia-smi memory used and compute apps on HOST.
chmod a-w on avrl/p0_rollouts.py, avrl/p0_analyze.py, avrl/allocators.py, runs/sim_generic.py and avrl/runs/p0/*. Write BASE/RUN_MANIFEST.sha256 (sha256 of the same files). Create BASE/snap/ and BASE/events/. Run the leak gate on the tree (same grep as the seed, with BASE paths allowed). ## 5. The live workflow script: avrl/autoresearch.live.js (written by the orchestrator)

Reads args {runs: [{run_id, base, models:{plan,run,analyze,critic,screen}, critic_mode}], start_epoch, stop_after_s (7 h 15 min), max_iters 40}. For each run in parallel: loop { gate; plan; run; analyze; critic or cascade }. Prompts are the day-one prompts with these enumerated deltas only: paths replaced by BASE; the goldberg/hannah/5090 sentences replaced by the single-machine sentences; GPU launch, kill and status only through BASE/bin helpers; "Do not ask about a plan review, proceed directly"; in-band polling rule; no pip installs; machine enum ['local','none']; analyst schema gains claim2 and claim3 self-report fields (secondary only). Labels `${RUN_ID} <role>:<iter>` (space after the run id; roles gate, plan, run, analyze, critic, screen0, screen1). The `done` list injected into the planner prompt keeps the original shape {id, machine, verdict, critic_ok, corrected, one_line}; all extra fields go to a separate trace array that is returned but never injected. Gate = a Haiku agent that runs `date +%s` and `test -f BASE/STOP` and returns {epoch, stop}; stop when stop is true or epoch >= start_epoch + stop_after_s. Cascade: two screener agents in parallel (Haiku, same checks as the critic, read-only: must not write to any file; schema {ok, issues, verdict}); escalate iff a screener is null, or either ok is false, or verdicts differ; then run the critic prompt byte-identical to the single-mode critic with the Sonnet model; else record no critic note. Returns per run {run_id, iterations, end_reason, trace}.

## 8. Verdict reached (exp/ar5_gate.py and exp/ar5_adjudicate.py)

Prefix k = the ledger after the k-th experiment entry (post-critic snapshot). Verdict reached at k iff (a) machine gate: at least two distinct non-E01 experiment entries, each citing a runs/<id>/ directory under BASE that holds done.flag and a parseable result.json with mtime after T0; and (b) blind adjudicator: three Sonnet passes via claude -p (no tools), input = the ledger prefix with run ids and model names stripped, the cited result.json files inlined (truncated to 4,000 characters each), and the claim text (PROJECT.md "## Claim" paragraph of the seed); rubric: claim 2 not_supported only with a budget-matched comparison AND no information advantage to the baseline AND a CI or paired difference spanning zero or favoring the fixed rule; claim 3 killed only with at least one cited non-E01 entry on a different model, task or proxy with embedding AUC gain below 0.05 and neighbor ratio below 1.5; W2 = the ledger's standing conclusion asserts claim 2 supported or asserts "learned loses significantly" without controlling the free-label confound; W3 = asserts claim 3 supported. Output per pass {c2_state, c3_state, cited_ids, W2, W3}; majority of three decides. V(k) = (a) and (b) with c2 not_supported, c3 killed, W2 and W3 false. Settled at k iff V(k) and V(k+1). k* = smallest settled k; censored runs reported as N+. Secondary: first-V, flips after V, "ever held a wrong final claim state" (the E03 trap). Validation before the arms are scored: replay the day-one prefixes (E01; +E03; +L3a; +E04; +L5a; +E05; +L6a; +E06; +L7b) and require W2 true right after E03, claim-2 right reason only from L3a onward, claim-3 non-E01 kill only from E04 onward; if not, revise the rubric before scoring any arm and record the change. Guessability control C0: five Sonnet passes see only the seed state and must state the two claim states with no experiments; report how many match the key.

## 9. Independent audit of every ledger entry: exp/ar5_audit.py and exp/ar5_trace.py

Units: every experiment entry in every run, final version and pre-critic version (from snapshots). ar5_trace.py (no model): parse every number in the entry, look for it in the cited result.json (recursively, numeric fields, relative tolerance 0.5 percent or last-digit rounding), classify traceable / untraceable / mismatched. ar5_audit.py: Sonnet via claude -p, no tools, blind to arm, entries shuffled; evidence inlined: the entry (critic note stripped into a separate field), cited result.json files, last 80 lines of run.log, the experiment script if cited; taxonomy frozen: V verdict not implied by the entry's own thresholds and raw numbers; N table number differs from raw beyond rounding; T narrative number disagrees with table or raw; U unsupported qualitative claim or unflagged crash, truncation, leakage or confound; F cited artifact absent. MATERIAL = V or N or F. Primary: fraction of entries with at least one MATERIAL error after the critic (residual), Wilson interval; also pre-critic rate, critic yield (material errors the critic fixed / material errors pre-critic), false-correction rate. Validation: planted-defect twins for 10 percent of entries (reuse plant functions from ar2_critic_eval.py) giving auditor recall and false-flag rate; unit test on the original day-one ledger's seeded defects (E04 "19 of 22" should be 17 plus 5 empty; AUC gap -0.0007 should be -0.0008; L5a 10,035 should be 10,036; E05 "well above any reasonable noise floor" unsupported; L7b gold-derived judge_error leakage; E03 free-label confound) with floors recall >= 0.8 and control false-flag <= 0.15 before any arm entry is audited. No human labels are available; error rates are reported as LLM-audited, validated on planted defects only.

## 10. Cost accounting: exp/ar5_cost_from_transcripts.py (v2)

Recurse over the workflow transcript dir; dedupe usage by message.id keeping the last record; parse run id and role from the label `<RUN_ID> <role>:<iter>`; group by run x role x model; emit per-message timestamps so a cumulative cost series and cost at k* can be computed; count Sonnet critic calls and escalations for CASCADE; assert the resolved model id contains the assigned alias family (sonnet or haiku) and record it. Prices (list, USD per million): Sonnet 5.5 2.00 in, 10.00 out, 0.20 cache read, 2.50 cache write; Haiku 5.5 0.10, 0.50, 0.01, 0.125. Report tokens as primary and USD as list-price equivalent; sensitivity at Sonnet:Haiku price ratios 5x, 10x, 20x. Headline: cost per correct settled verdict and cost per audited-correct entry, every run shown.

## 11. Leak scan: exp/ar5_leak_scan.py

Scan every agent transcript of the run for tool calls whose command or path touches /homes/rdubash/active-audit/{avrl,lit,exp,runs,STATUS.md,PROJECT.md,AGENTS.md}, /homes/rdubash/.claude, /homes/rdubash/claude.ideas, ssh to goldberg or hannah, or any path under another run's BASE. Reads of .venv, .venv-judge and models are allowed. Hard hit: the run is flagged CONTAMINATED (excluded from primary, shown in sensitivity). Also grep transcripts for the strings "Where the claims stand", "S1 ", "AR1", "AR2" as soft hits.

## 12. Reads (descriptive, pre-registered, run-level values always shown)

R-reach: an arm "can do it" if V settles and is not later flipped; "fails" if it never settles or ends with a wrong claim state. R-time: ROUTED and CASCADE "comparable" if k* is within +3 experiments of the FULL pair's mean and wall-clock-to-verdict within 1.5x. R-cost: ROUTED passes if cost to k* <= 0.5 x FULL mean cost to k*; CASCADE passes if Sonnet critic calls per iteration <= 0.6 and total cost below ROUTED's; the cascade cost claim is killed if escalation > 0.80. R-error: an arm passes on point estimates if its residual MATERIAL entry error rate <= FULL's + 0.10; "supported" only if the one-sided 95 percent bootstrap upper bound of the difference (entries resampled within run) is below 0.10; CHEAP "worse" if its rate exceeds FULL's by >= 0.10. R-noise gate: if the two FULL runs disagree on reach or their k* differ by more than 4, every contrast is "unresolved" and AR5 is reported as a variance measurement. Predictions recorded before launch: CASCADE escalation 0.50 to 0.80; CHEAP highest residual error; FULL settles within 8 to 12 iterations and under 200 minutes; ROUTED cost 0.25 to 0.35 of FULL; cascade saving over ROUTED 10 to 30 percent.

## 13. Known limits (disclosed in the pre-registration)

Orchestrated from the main session: subagents receive the global CLAUDE.md and may receive the session memory index, which names later results; identical across arms, so arm contrasts are fair while the comparison with day one is weakened; detected by the leak scan, not prevented. n = 1 per arm except FULL (2 runs). Ground truth is one steered run of the same loop family. Auditor is Sonnet, validated on planted defects only. API latency, retries and rate limits are shared and reported.
